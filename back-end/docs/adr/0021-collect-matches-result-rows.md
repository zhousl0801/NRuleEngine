# ADR-0021：独立多命中求值与统一结果行

- **状态**：已接受
- **日期**：2026-10-16
- **关联**：ADR-0011、ADR-0012、ADR-0020；[执行结果契约](../architecture/execution-results.md)

## 上下文

现有 FirstMatch 和 Sequential 都只产生一份出口；NumericRange 和 List 表示单次赋值的值形状。尺寸推导需要保留多条命中的宽、厚、长及公差对应关系。项目尚未被业务系统集成。

## 决策

由场景固定 Single/Many 结果基数。Single 允许 FirstMatch、Sequential，Many 使用 CollectMatches。跨模型仍只选择唯一绑定；CollectMatches 在该模型内部让每条规则从相同入口与默认值独立计算，按优先级和顺序返回完整结果行。

试算与运行共享 Results 行结构，每行含原生 JSON 出口与来源规则标识。Sequential 返回一个合并行，CollectMatches 不跨规则覆盖、追加或去重。复用现有 Scalar、NumericRange、List，不增加任意业务对象类型。全部规则计算成功后才交付结果；无命中、计算错误和资源超限明确区分。

门禁改为预期状态及有序出口数组，排除复制修订会变化的来源规则 ID。结果基数、模式和门禁共同进入修订快照及哈希。详细限制以执行结果契约为准。

## 考虑过的替代方案

- 将候选拆成多个独立数值列表会失去尺寸与公差之间的关联，且候选字段可能重复，不采用。
- Sequential 的首写或末写策略只保留一份结果，无法保留多个候选，不用于模拟收集。
- ConditionSet 加宿主保存常量结果仍可用于纯资格判断，但计算型条件和出口需要在同一修订中发布，因此提供 CollectMatches。

## 后果

调用方统一消费结果行，并按行组装业务对象；发布门禁必须覆盖行数、顺序及完整出口。DTO 和存储直接使用新契约，不维持旧顶层 Outputs、OutputsJson 或旧门禁格式，已有开发数据库需要明确重建。结果限制固定为 100 行、65536 字节；未来业务量超出时需重新评估资源边界。
