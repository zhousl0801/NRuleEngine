# ADR-0017：首版表达式类型与确定性顺序

- **状态**：已接受
- **日期**：2026-09-23
- **关联**：ADR-0007；系统设计草案 §6、§8

## 上下文

表达式 AST、变量类型和规则顺序会进入发布快照，必须在开始编制前确定可序列化且可重复执行的语义。

## 决策

变量 `StableKey` 使用 Guid，跨修订复制保持原值，删除再建生成新值。首版类型为 Decimal、String、Boolean、Enum；数值计算只使用 `decimal`，数据库列按精度 28、小数位 10 存储配置中的数值，超界或精度不符时拒绝，不隐式转为 `double`。AST 首版节点限于类型化常量、变量引用、逻辑与比较、四则运算、空值判断、集合包含及白名单函数 `Abs`、`Min`、`Max`、`Round`、`Coalesce`。不执行任意方法、反射或外部 I/O；节点格式带版本号，未知版本拒绝执行。

规则按 `Priority` 降序、同优先级 `SortOrder` 升序执行；同一修订中同级顺序值必须唯一，发布前拒绝冲突。展示顺序不决定执行顺序。

## 考虑过的替代方案

- 使用可读字符串作稳定键：易与可修改的 Code 混淆。
- 使用 `double`：二进制浮点误差不适合尺寸数值规则。
- 同级规则按数据库返回顺序执行：结果不稳定。

## 后果

- 存储格式和函数签名须版本化；后续增加类型或函数必须保留旧修订解释能力。
- 本阶段仅建立变量类型和稳定键；AST、执行与完整顺序校验在后续阶段实现。
