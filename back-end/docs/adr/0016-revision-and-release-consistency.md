# ADR-0016：修订一致性边界与发布事务

- **状态**：已接受
- **日期**：2026-09-23
- **关联**：ADR-0006、ADR-0011；系统设计草案 §6、§9

## 上下文

草稿的变量、规则、赋值、绑定和门禁用例共同形成完整语义快照；发布还需更新模型活动指针并写发布记录。并发发布可能同时通过跨模型绑定歧义检查。

## 决策

`RuleModelRevision` 是草稿内容的一致性边界，内容修改必须检查其乐观并发戳。`RuleModel` 保存活动修订指针和独立并发戳。发布时在同一数据库事务内完成完整校验、跨模型歧义检查、修订状态及哈希固定、活动指针切换和 `ReleaseRecord` 写入；检查期望的模型及修订并发戳。对同一 `AppCode + ScenarioCode` 的竞争发布采用数据库可保证的串行化或等效锁，不能仅依靠进程内锁。提交后失效缓存；缓存读取仍须以发布版本为键。回滚沿用同一事务与并发协议，历史修订内容不变。

## 考虑过的替代方案

- 分步提交发布内容与活动指针：调用方可能看到不完整状态。
- 仅使用模型并发戳：无法阻止草稿编辑与发布互相覆盖。
- 仅使用进程内锁：多实例宿主之间不生效。

## 后果

- Revision 与 Model 各自有并发戳；跨模型发布还需要数据库级协调。
- 首批草稿实现建立实体和约束，发布事务在后续阶段实现，不提前宣称发布能力。
- 缓存失效失败不能让旧版本永久作为当前版本；运行时以活动指针为准。
