# ADR-0003：核心仓库不提供 ODS 集成包

- **状态**：已接受
- **日期**：2026-09-21
- **关联**：产品设计草案 §2.4；系统设计草案 §5.5、§11 技术验收标准

## 上下文

核心不包含 ODS、尺寸、机组、钢种等专有领域对象，场景契约和业务资源由接入应用注册（产品设计 §2.4）。

`IRuleBindingValueProvider` 的实现必须放在接入 App 中，通过依赖注入调用仓储；NRuleEngine 核心不能反向依赖业务仓储（系统设计 §5.5）。示例实现 `OdsMachineBindingValueProvider` 在文档里是作为**接入方写法示例**出现的，不是核心的一部分。

技术验收标准中有一条是「仓库不存在生产 Host 和 ODS 依赖」（系统设计 §11）。

> **待补**：
> - 是否考虑过在核心仓库放一个「集成示例」项目（不含业务依赖，只演示 Provider 怎么写）？现在是靠文档里的代码示例代替吗？
> - 如果第二个、第三个接入方出现，Provider 的样板代码是否值得抽成核心里的抽象基类？

## 决策

核心仓库不提供 `NRuleEngine.Integrations.Ods`；ODS 接入代码留在 ODS 仓库。

## 考虑过的替代方案

> **待补**：是否评估过以下方向，以及为什么没选：
> - 核心仓库提供 `NRuleEngine.Integrations.*` 系列集成包；
> - 单独开一个 integrations 仓库承载所有接入方的适配代码。

## 后果

- 每个接入方自己实现 Provider 并承担其维护成本。
- 核心保持领域无关，可以被非 ODS 的应用直接引用（这是本决策的主要收益）。
- 接入方之间无法共享适配代码，重复实现的风险由各仓库自行承担。

> **待补**：接入方数量增长后的取舍（是否会出现必须抽公共包的时点）。
