# ADR-0002：被宿主引用的通用组件，不提供自有 Host

- **状态**：已接受
- **日期**：2026-09-21
- **关联**：产品设计草案 §2.4、§3 非目标；系统设计草案 §3 仓库结构、§4 ABP 模块依赖、§5.5

## 上下文

NRuleEngine 以标准 ABP Module 形式供业务应用引用，核心不包含 ODS、尺寸、机组、钢种等专有领域对象；场景契约和业务资源由接入应用注册（产品设计 §2.4）。

系统设计草案的仓库结构明确不含 `HttpApi.Host`、`DbMigrator` 或任何具体业务应用的集成项目，并规定**数据库迁移由宿主应用的 DbMigrator 执行**，组件只提供 EF Core 模型配置和迁移集成能力（系统设计 §3）。

宿主按需引用模块：Domain / Application / EntityFrameworkCore / HttpApi 各引用对应模块，DbMigrator 由宿主负责执行最终迁移（系统设计 §4）。

Provider 实现必须落在接入 App 中，**NRuleEngine 核心不能反向依赖业务仓储**（系统设计 §5.5）。

> **待补**：
> - 组件是否需要一个最小可运行的测试宿主，还是只靠单元测试？系统设计 §11 提到了「示例测试宿主」，它与生产 Host 的边界在哪？
> - 无自有 Host 意味着没有独立的健康检查、配置入口和日志出口，这些由宿主提供是否都成立？

## 决策

NRuleEngine 是被其他 ABP 应用引用的通用组件，不提供自有 Host。

## 考虑过的替代方案

文档中已被排除的方向：

- **独立部署成必须通过 HTTP 调用的平台**——产品设计 §3 明确列为非目标。

> **待补**：是否评估过「同时支持内嵌引用和独立部署两种形态」？如果评估过，为什么不做？

## 后果

- 没有独立部署形态，没有自己的配置、迁移和运维入口。
- 迁移责任转移给宿主，组件的模型变更必须能被宿主的迁移流程接纳。
- 组件不能反向依赖任何业务仓储或领域实体，接入必须通过代码注册的契约完成。
- 契约变更的影响面是「所有引用它的宿主应用」，需要明确兼容策略（与 ADR-0010 相关）。

> **待补**：宿主升级组件版本时的兼容性要求（能否要求宿主必须同步升级）。
