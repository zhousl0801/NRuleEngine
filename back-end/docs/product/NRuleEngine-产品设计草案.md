# NRuleEngine 产品设计草案

> 状态：讨论稿  
> 版本：v0.9  
> 日期：2026-09-23  
> 范围：产品能力、用户交互与产品验收  
> 设计基线：与《NRuleEngine 系统设计草案》v0.9 对齐

## 1. 文档边界

NRuleEngine 是一个从零设计的通用规则编制与运行组件。它采用 ABP 模块结构，预期被 ODS 等 ABP 应用直接引用。

本文只描述产品层设计。技术架构、数据模型和接口见 [NRuleEngine 系统设计草案](../architecture/NRuleEngine-系统设计草案.md)。

### 1.1 首版交付边界

首版只交付后端领域能力和 HTTP API，不交付编制台前端。API 的对象模型、错误模型和交互闭环稳定后，再单独开展前端产品设计和开发。

| 优先级 | 首版范围 |
|---|---|
| P0 | App/场景代码注册、模型与草稿、变量、规则与赋值、场景绑定、校验、简化试算、发布、回滚、运行时执行 |
| P1 | 版本差异、规则包跨环境导入导出、增强型运行诊断 |
| 延期 | 前端编制台、AllMatches、审批流、变量敏感标记、复杂对象编辑体验 |

## 2. 核心目标

### 2.1 可编制

- 维护入口、中间和出口变量。
- 编制规则条件和赋值。
- 每次赋值独立选择常量或表达式。
- 表达式可以引用入口变量以及已计算的中间、出口变量。
- 变量改名不破坏已有结构化引用。

### 2.2 可运营

- 首版通过后端 API 完成常规规则维护，后续编制台直接使用同一套 API 支持业务人员自助操作。
- 草稿与线上版本隔离。
- 支持校验、发布、回滚、审计和并发冲突提示。
- 删除或停用前可以查看引用和影响范围。

### 2.3 可验证

- 保存时校验引用存在、基础语法和类型。
- 发布时校验完整依赖图、循环、场景绑定歧义及发布门禁用例。
- 试算展示场景解析、逐规则命中、变量取值、赋值过程和错误位置。

### 2.4 易于集成

- 以标准 ABP Module 形式供业务应用引用。
- 核心不包含 ODS、尺寸、机组、钢种等专有领域对象。
- 场景契约和业务资源由接入应用注册。

## 3. 非目标

### 3.1 长期边界外

- 兼容旧 RuleEngine 的表结构和接口。
- 自动迁移旧规则数据。
- 通用 BPM 审批流。
- 任意脚本执行或表达式内直接访问数据库、网络和文件。
- 将 NRuleEngine 独立部署成必须通过 HTTP 调用的平台。

### 3.2 首版延期项

- 首版不实现变量级敏感标记和自动脱敏。
- 首版不提供前端编制台。
- 首版不实现 `AllMatches`。
- 首版不持久化完整试算过程或生产执行 Trace。

## 4. 用户角色

以下角色描述完整产品形态中的职责。首版只提供后端 API，因此角色通过 API 权限和宿主应用体现：

| 角色 | 主要行为 |
|---|---|
| 规则维护者 | 建模、维护变量、规则、赋值和场景绑定，执行校验与试算 |
| 规则发布者 | 检查变更并发布、回滚 |
| 规则使用者 | 在业务流程中执行已发布规则，查看允许范围内的执行结果 |
| 组件接入开发者 | 通过代码注册 App、场景、函数、类型和资源值提供器 |

这些角色用于描述职责，不等于首版必须实现四套细粒度权限。首版只保留少量应用级权限：`Manage`、`Publish`、`Execute`；如果接入应用认为发布无需单独控制，也可以把 `Publish` 合并进 `Manage`。

## 5. 核心产品概念

| 概念 | 产品含义 |
|---|---|
| App | NRuleEngine 的接入应用边界，例如 `ODS`，由稳定的 `AppCode` 标识 |
| 场景 | 应用注册的规则用途，例如尺寸展开、机组参数计算 |
| 规则模型 | 可独立编制、发布和执行的一组规则 |
| 修订 | 规则模型的一份完整快照；草稿可编辑，发布后不可变 |
| 变量 | 场景和规则使用的入口、中间、出口数据 |
| 规则 | 条件与一组赋值的组合 |
| 赋值 | 向目标变量写入常量或表达式结果 |
| 场景绑定 | 使用结构化维度把业务上下文匹配到已发布规则模型 |
| 发布 | 将通过校验的修订原子地切换为运行版本 |

一级接入边界统一表述为 `App`，使用 `AppCode` 作为稳定标识。

## 6. 产品能力

### 6.1 应用与场景目录

- 通过只读 API 返回当前宿主中已注册的 App 和场景。
- App 完全由接入应用通过代码注册，不能在界面或 API 中新增、修改或删除。
- 展示每个场景允许的入口、出口、绑定维度、类型和函数。
- 场景由接入应用通过代码注册，业务用户不能随意创建与代码契约不一致的场景。
- 场景契约变更时显示版本和兼容性状态。

### 6.2 规则模型管理

- 创建、复制、归档和查询规则模型。
- 从当前发布版本创建草稿。
- 对比草稿与发布版本（P1）。
- 查看当前线上版本、历史发布和回滚记录。

### 6.3 变量编制

- 场景契约定义入口变量和必需出口变量；其编码、方向和类型不能由规则维护者修改。
- 创建规则模型时，从场景契约实例化入口和必需出口变量。
- 创建仅供模型内部使用的中间变量。
- 首版不允许创建场景契约未声明的出口变量。
- 对允许编辑的变量属性配置名称、默认值、单位和精度。
- 展示变量被哪些条件、赋值和测试用例引用。
- 删除前执行影响分析。

### 6.4 规则与赋值编制

- 后端 API 支持比较、逻辑、空值和集合判断；前端条件编辑器留待后续设计。
- 后端 API 接收并校验表达式；专家模式和变量、函数提示留待前端阶段。
- 每条赋值独立选择常量或表达式。
- 表达式编辑器展示类型错误和源位置。
- 规则优先级与界面显示顺序分离。

### 6.5 场景绑定

调用方先选择 App 和场景，目录 API 根据场景声明返回绑定维度及候选值；未来编制台据此动态生成绑定表单。例如 ODS 尺寸展开可以出现产品类别、工艺路径或规格范围，而机组参数可以出现机组或工序资源。

绑定保存前校验字段、操作符和值类型；发布前校验相同优先级下是否存在重叠或歧义。

同一个 `AppCode + ScenarioCode` 允许存在多个已发布规则模型。运行时在所有命中绑定中选择数值优先级最高的一项；最高优先级出现多个命中结果时视为歧义，不能继续执行。发布校验应尽可能提前阻止同优先级重叠绑定。

### 6.6 校验、试算和回归用例

| 阶段 | 校验重点 |
|---|---|
| 保存 | 当前对象的语法、类型和引用存在性 |
| 完整校验 | 整个修订的依赖、循环、写入冲突和场景绑定 |
| 试算 | 使用输入和场景上下文执行，但不影响线上版本 |
| 发布 | 完整校验、发布门禁用例、并发版本和发布资格 |

首版试算用于验证表达式和输入输出正确性，不承担生产诊断、历史追踪或长期留存职责。试算结果至少包括：

- 使用的应用、场景、绑定和修订。
- 命中的规则及其条件结果。
- 表达式计算结果和最终输出。
- 错误所属规则、表达式和字符范围。

试算结果随 API 响应返回，首版不落库。

### 6.7 发布与回滚

- 发布版本不可修改。
- 草稿修改不会影响运行时。
- 发布切换对调用方原子可见。
- 回滚通过重新激活历史发布修订完成，并生成新的发布记录。
- 并发发布必须检查期望版本，禁止静默覆盖。

## 7. 核心交互流程

### 7.1 创建并发布规则

```mermaid
flowchart LR
    A[通过API选择App与场景] --> B[创建规则模型]
    B --> C[维护变量]
    C --> D[编制条件和赋值]
    D --> E[配置场景绑定]
    E --> F[完整校验]
    F --> G[试算与回归用例]
    G --> H[发布]
    H --> I[业务运行时使用]
```

### 7.2 并发编辑

1. 用户打开草稿时取得 `ConcurrencyStamp`。
2. 每次保存携带该值。
3. 服务器发现版本已变化时拒绝覆盖。
4. API 返回冲突版本及可比较信息；未来 UI 负责展示差异并让用户重新应用变更。

### 7.3 删除与影响分析

1. 用户请求删除变量、规则模型或其他可编辑对象。
2. 系统先返回直接和间接引用。
3. 有阻塞引用时不执行删除，并提供跳转入口。
4. 用户清理引用后再次删除。
5. 已发布快照始终保留，不因新草稿删除对象而被改写。

## 8. 首版执行语义

### 8.1 命中模式

| 模式 | 语义 | 跨规则读取前序结果 |
|---|---|---|
| FirstMatch | 第一条命中规则赋值后停止 | 否 |
| Sequential | 按顺序执行并把赋值写回共享上下文 | 是 |

首版只实现 `FirstMatch` 和 `Sequential`。同一变量多次写入的候选策略为 `ErrorOnMultipleWrite`、`FirstWriteWins` 和 `LastWriteWins`，建议默认 `ErrorOnMultipleWrite`。

### 8.2 运行失败语义

运行结果统一分为：

- `Succeeded`：成功产生全部必需输出。
- `NotMatched`：存在已发布模型，但当前上下文未匹配任何绑定。
- `Rejected`：契约、输入或模型选择不满足执行前提。
- `Failed`：已经进入规则计算，但表达式、函数、变量赋值或输出校验失败。

`NoMatchingBinding` 等可预期结果通过结构化执行结果返回；数据库不可用、程序缺陷等不可预期故障通过异常通道处理。NRuleEngine 不自动回退到旧版本，ODS 如需兜底必须显式实现。

运行 API 对 `Succeeded / NotMatched / Rejected / Failed` 统一返回 HTTP 200。未在场景契约中声明的额外输入被严格拒绝。执行同时响应调用方取消令牌和引擎内部时间预算。

完整错误码和安全定位字段见 [运行错误与异常模型](../architecture/runtime-error-model.md)。

## 9. 产品验收标准

### 9.1 编制与验证

- 调用方可以通过后端 API 完成模型、变量、规则、赋值和场景绑定的维护。
- 场景契约定义的入口和必需出口不能被规则维护 API 改变。
- 同一输出变量能在不同规则中分别接受常量或表达式赋值。
- 结构化引用不因变量改名而失效。
- 不存在的引用、类型错误、循环依赖和绑定歧义不能进入发布状态。
- 试算可以解释规则为什么命中或未命中。

### 9.2 运营

- 草稿不影响当前运行结果。
- 发布版本不可修改，可以回滚。
- 并发编辑不会静默覆盖。
- 可以查看变更人、时间、变更摘要和发布历史。
- 删除前可以查看影响面。

### 9.3 集成

- 接入方通过 ABP Module 引用组件，无需部署 NRuleEngine 自有 Host。
- 接入应用可以注册场景、类型、函数和资源值提供器。
- NRuleEngine 核心项目不依赖 ODS。
- 运行时可以按 `AppCode + ScenarioCode + Context` 定位并执行已发布规则。
- 同一场景存在多个已发布模型时，按绑定优先级选出唯一模型；最高优先级并列时返回歧义错误。

## 10. 产品层开放问题

1. `Publish` 是否需要与 `Manage` 分权，还是由接入应用自行决定？
2. 场景契约升级后的旧修订按其锁定的契约版本运行；宿主须保留被引用的旧契约。见 [ADR-0015](../adr/0015-pinned-scenario-contract-version.md)。
3. 首版绑定不包含生效期。见 [ADR-0018](../adr/0018-no-binding-effective-period-v1.md)。
4. 前端设计启动时采用哪种技术栈，以及以宿主页面还是可嵌入 UI 包交付？
