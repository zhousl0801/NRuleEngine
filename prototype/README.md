# NRuleEngine 前端产品原型

打开 [index.html](index.html) 即可查看交互原型，不需要构建或后端服务。场景下多规则集的静态预览见 [场景规则集.png](场景规则集.png)；单个规则集编制页见 [规则编制工作台.png](规则编制工作台.png)。[规则维护交互流程](rule-maintenance.html)展示规则、条件、赋值、影响、校验、试算和并发冲突状态，对应[静态预览](规则维护流程.png)及[流程设计](规则维护流程.md)。页面使用演示数据，未调用真实 API。色板参照宿主订单设计系统：海军蓝导航、石板蓝内容面板、蓝色操作强调，绿色与红色分别表示成功和错误。

规则维护页支持嵌套 AND / OR 条件组。赋值公式栏可直接编写多变量计算，并从快捷区插入变量或符号；页面解析为 AST 后再用于演示保存。赋值卡片右上角的 × 会先打开删除影响确认。

## 界面文案

- 页面标题、辅助说明和状态标签使用中文；规则集编码、变量编码、修订号及公式保留其实际数据格式。
- 界面不展示测试应用名称或“演示数据”等原型说明；原型与真实服务的边界在本文档说明。
- 操作按钮使用简短动词与对象，如“编辑”“查看”“试算”；仅在需要区分对象时补充名称。
- 侧栏导航只展示图标和名称，不附加规则集、条件集的数量标记。

## 功能分区

| 区域 | 用户要完成的事 | 对应现有后端能力 |
| --- | --- | --- |
| 场景 | 按规则集或条件集类型选择场景；查看输入数据、计算结果和适用范围 | 目录查询、场景描述 |
| 规则集列表 | 跨场景查看与筛选，明确所属场景后创建、复制和管理规则集 | RuleModel 列表、创建、复制、归档 |
| 规则集编制 | 在选中规则集的草稿中编制变量、规则和场景绑定 | 修订、变量、规则、赋值、绑定维护 |
| 校验与试算 | 在发布前定位结构问题，按输入观察命中规则、赋值及出口 | 完整校验、草稿试算 |
| 门禁与发布 | 管理回归用例，检查发布条件，切换活动修订 | 门禁用例、发布、回滚、发布记录 |
| 条件集 | 对明确候选编制布尔条件，使用正反样本发布 | 条件集、候选判定、条件集发布与回滚 |

界面中的“规则集”与后端 **RuleModel 一一对应**，不是新增的持久化实体，也不是 RuleModel 的上层容器。层级为 `App → 场景 → 多个规则集（RuleModel）→ 各自的修订 → 规则 → 赋值`。同一 `AppCode + ScenarioCode` 可有多个活动发布模型；运行时比较**所有命中场景绑定**的优先级，唯一最高者所属的模型被执行，并列最高则返回 `AmbiguousBinding`。优先级属于绑定，不是规则集的全局属性。

选中规则集后，内部采用“规则 / 变量 / 场景绑定 / 门禁用例 / 版本”的分区。规则集的核心产物是赋值与必需出口；条件集的核心产物是布尔判定，二者不共用同一个编辑器。发布流程沿“编制草稿 → 完整校验 → 试算与门禁 → 发布切换”排列，草稿和线上状态同时可见。

## 多个场景与场景内多个集合的交互

- 场景页按规则集、条件集类型分区，每个分区用响应式卡片网格展示多个场景。支持按场景名称或编码搜索；卡片展示用途、当前在用集合数量和入口。展开说明时卡片占满该分区宽度，明细表可横向滚动。
- 侧栏“规则集”“条件集”始终进入全部场景列表，不默认选择场景或某个集合。列表每项注明所属场景，提供所属场景、名称或编码、维护状态筛选；场景卡片则进入带有明确场景筛选的列表。无效场景显示找不到提示，不回退到其他场景。
- 新建集合必须明确所属场景：全部列表中先选择场景，从场景列表新建时固定为当前场景。暂无集合的场景保留入口，进入后可创建第一个集合。复制始终保留来源场景。侧栏不展示数量标记。
- 列表同时呈现线上与草稿修订，点击修订标签可直接查看对应快照。没有草稿时先查看线上内容，再“从线上创建草稿”；已有草稿时直接继续编制。详情顶部仅可切换同一场景内的其他集合，返回时保留列表的场景、搜索与维护状态。规则维护页也携带列表场景范围；直接打开详情而未指定集合时返回全部列表。
- 每个规则集使用自己的规则、赋值和场景绑定。新建规则集从空规则、空绑定开始；复制时明确选择线上或草稿来源，生成独立规则集及首个草稿。规则维护页通过集合标识读取和保存对应内容，返回详情时继续定位到原规则集与修订。
- 条件集列表呈现已发布修订的判定优先级，详情独立编辑草稿中的优先级与条件。当前编辑器覆盖入口宽度与产品类别的 AND 判定；切换修订时显示各自的条件、样本验证状态与只读状态。未保存修改离开前需确认，保存草稿不会改变线上候选。
- “试算已发布候选”先明确场景，再选择该场景内的候选范围，切换场景时清空上次结果。禁止混用不同场景的候选，并提供全部命中、首条命中两种预览。没有命中与最高优先级并列命中分别反馈；该预览只使用已发布条件，正式结果仍由后端判定服务提供。
- 归档前说明当前发布修订停止参与后续运行的影响；归档后可通过“已归档”筛选只读查看。发布检查提供待完成检查的说明，原型不会自动发布、回滚或切换线上修订。

集合状态保存在当前标签页的 `sessionStorage` 中，供列表、详情与规则维护页共享。已保存内容在同一标签页刷新后保留，关闭标签页结束；未保存的编辑只在当前页面存在。浏览器禁用会话存储时退回页内状态，跨页保留需要在允许会话存储的同源环境下验证。

联调缺口：当前条件集后端服务没有按场景列出集合的查询接口，列表需要补齐该查询；本次新建、复制、创建草稿、保存和归档均是原型本地状态操作。条件集复制没有对应后端能力，原型不提供此入口。当前变量与绑定维度仍采用既有场景样例，完整 AST 编辑、样本维护和发布结果需要接入正式 API。

## 场景说明展示规划

场景页按类型分区。卡片展示场景名称、用途及规则集或条件集入口，输入、结果和适用范围的明细统一收纳在可展开的“查看场景说明”中。说明只读，不在场景页维护变量或选择场景版本。

| 后端描述字段 | 产品展示 | 展示规则 |
| --- | --- | --- |
| `AppCode` | 所属应用范围 | 由宿主应用上下文确定；当前嵌入原型不展示测试应用编码 |
| `ScenarioCode` | 场景编码 | 在展开说明中展示，用于定位场景 |
| `ContractVersion` | 不展示 | 用于内部解析定义；已有规则修订保留其自己的变量与类型快照 |
| `Inputs` | 输入数据 | 在展开说明中显示 `Name`、`Code`、类型及取值要求 |
| `RequiredOutputs` | 必须产出的结果 | 展示每项结果的名称、编码、类型及取值要求；包含数值区间和列表等结构 |
| `BindingDimensions` | 可设置的适用范围 | 显示条件名称、编码、类型和 `AllowedOperators` 对应的中文比较方式；具体可选业务值不由此字段提供 |

变量类型由 `RuleTypeDescriptor` 的 `Kind` 与 `Shape` 共同呈现，例如数值、数值区间和文本列表。取值要求展示可空性；配置了数值总位数、小数位数或枚举编码时再补充相应约束。可空性不等同于是否必须传入，输入缺失时还可能使用规则修订配置的默认值。中间变量属于规则集修订，不计入场景的输入或结果数量。

条件集采用 `ConditionScenarioDescriptor.Inputs` 在展开说明中展示输入数据，并说明判定用途。该描述对象没有业务输出变量与场景绑定维度，不套用规则集场景的结果表和适用范围表。

场景说明中的变量与现有编制页保持一致：尺寸展开有 2 项输入、5 项结果、2 项适用范围条件；候选适用判定有 2 项输入。为验证多个场景的布局，另设精整宽度修正、试验规格展开，以及精整候选筛选、试验候选判定，规则集类现含 4 个场景、条件集类含 3 个场景；尺寸展开含 3 个规则集，精整宽度修正含 2 个规则集；候选适用判定、精整候选筛选各含 2 个条件集；两个试验场景初始为空。新增场景复用现有宽度与产品类别数据结构。这些是原型展示数据，与本地 Host 的注册数据不同，尚未调用目录 API，也未新增后端注册。加载新增样例时保留当前会话内已保存的编辑和归档状态。

联调前需明确两项展示数据来源：当前两个场景描述对象均没有中文场景名称和用途说明字段，原型中的名称、说明暂由展示配置提供；当前目录查询可返回同一场景的多个契约版本，宿主还需明确供场景页展示的当前定义，不能按版本字符串排序推断“最新”。

## 设计边界

- 嵌入宿主应用，不设计登录、账号中心或独立站点外壳。
- 应用与场景由宿主代码注册，因此目录只读；契约入口和必需出口不可在界面中自由改动。
- 不将演示用的“尺寸展开”变量、数值和状态视为真实业务契约。正式实现需要读取场景契约和实际修订数据。
- 原型中的校验、试算和发布检查为示意反馈。实际成功与否必须依据服务端结果，不能依据页面状态推断。
- 规则维护页的新增、保存与删除只修改当前标签页的演示状态；已保存状态按上述会话存储规则保留，不会写入项目数据库。
- 不展示持久化的生产执行 Trace；当前组件只返回简化试算结果，未提供完整 Trace 存储。

## 区间与候选列表

规则维护页增加宽度范围、候选宽度和候选编码出口。端点和候选项独立选择常量、数值公式或同类型变量；列表可添加、删除及上下移动。包含两端的范围要求最小值不大于最大值，列表保留顺序并限制为 1–100 个非空、不重复候选。页面按目标契约生成常量 JSON 或 range/list AST，正式行为见[输出值契约](../back-end/docs/architecture/output-values.md)。浏览器计算只供交互预览，数值精度与正式结果以服务端为准。

## 结果行预览

“候选规格计算”场景锁定多行结果，已有两个重叠候选规则。维护页对已保存、已启用规则按优先级和顺序预览，收集模式每条规则使用同一份入口和默认值；成功展示 Results 中每行的 SourceRuleIds 与 Outputs。其他场景按首条命中返回一行。结果保留重复字段值和完整行关系，后续失败不显示部分行。场景说明展示单行或多行要求，不提供随意切换基数的控件。

此预览未调用后端，也不代替服务端 decimal、绑定及发布校验。正式结果契约见[执行结果契约](../back-end/docs/architecture/execution-results.md)，后端新多行联调场景为 DEMO/matched-results。
