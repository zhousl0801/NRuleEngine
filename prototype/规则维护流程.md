# 核心规则维护流程设计

## 定位

入口为 `App → 场景 → 规则集（后端 RuleModel）→ 草稿修订 → 规则`。本流程维护赋值型规则模型中的一条规则及其赋值；条件集（ConditionSet）的布尔判定编制是另一条流程。宿主负责身份与权限，原型不设计登录。

[打开交互原型](rule-maintenance.html)；从[场景规则集原型](index.html#model-list)进入“尺寸展开规则”，再点“新建规则”或“编辑规则”也可到达。

## 主流程

```mermaid
flowchart LR
    A[选择规则集与草稿] --> B[选择或新增规则]
    B --> C[填写名称、优先级、同级顺序和启用状态]
    C --> D[用变量、操作符、值编制布尔条件]
    D --> E[保存规则与条件]
    E --> F[逐条添加或修改赋值]
    F --> G[逐条保存赋值]
    G --> H[完整校验草稿]
    H --> I[输入场景上下文和入口变量试算]
    I --> J[返回规则集维护门禁用例及发布]
```

规则和赋值分别由不同 API 写入。原型的“下一步”只切换视图，不代表自动保存。规则新增后可先不含赋值；完整校验与发布门禁负责发现必需出口缺失等整份修订问题。

## 页面分区

| 区域 | 内容与行为 |
| --- | --- |
| 左侧规则列表 | 当前修订中的规则、优先级、赋值数量、保存状态；新增和切换规则 |
| 规则与条件 | 名称、优先级、同级顺序、启用状态；用可嵌套条件组在每一层选择 AND / OR，生成布尔 AST；显示可读条件与可展开的条件结构 |
| 赋值动作 | 每条赋值独立选择目标、常量或表达式；公式栏直接编写多变量计算，可从快捷区插入变量与符号；卡片右上角删除入口先展示影响 |
| 校验与试算 | 展示完整校验的问题路径，以及试算所需的场景上下文、入口和结果位置 |
| 右侧状态 | 草稿/线上状态、未保存改动、当前并发戳、场景变量及并发冲突恢复入口 |

## 接口和状态衔接

| 操作 | 后端接口或契约 | 关键界面状态 |
| --- | --- | --- |
| 打开规则集 | `GetRevisionsAsync`、`GetRevisionAsync` | 默认进入草稿；已发布修订只读 |
| 新增/修改规则 | `AddRuleAsync` / `UpdateRuleAsync` | `AddRuleDto` 包含名称、优先级、顺序、启用状态、`ConditionAstJson` 和期望并发戳 |
| 新增/修改赋值 | `AddAssignmentAsync` / `UpdateAssignmentAsync` | 每条赋值选择目标 `StableKey`、`Constant` 或 `Expression`，提交新的期望并发戳 |
| 删除前影响 | `GetRuleRemovalImpactAsync` / `GetAssignmentRemovalImpactAsync` | 先展示路径和下游影响；规则与赋值的影响为提示，不因引用自动阻止 |
| 删除规则/赋值 | `RemoveRuleAsync` / `RemoveAssignmentAsync` | 使用影响预览返回的当前并发戳；删除后提示重新校验 |
| 完整校验 | `IRuleValidationAppService` | 按问题 `Path`、`Code` 和可选源码位置引导回对应编辑对象 |
| 草稿试算 | `IRuleSimulationAppService` | 指定修订、`ContextJson` 和 `InputsJson`；显示命中绑定、条件、赋值、出口或错误路径；不持久化完整 Trace |

每次成功写入都应使用响应中的新 `ConcurrencyStamp` 更新当前草稿。遇到 `ConcurrencyConflict` 时停止后续写入，重新读取修订，提示用户核对本地修改后再继续；不能静默覆盖。原型在维护状态区用红色提示冲突，并提供刷新草稿入口；刷新后提示核对本地修改，再由用户重新保存，未连接真实服务器。

## 条件与表达式边界

- 条件和表达式的权威内容是 AST v1；`ConditionSource`、`ExpressionSource` 只供展示，不能把任意输入的文本直接当作可执行表达式。
- 条件可嵌套分组，每组独立选择 AND 或 OR；可表达 `(A AND B) OR (C AND D)`。主组无条件表示始终满足，空子组不能保存。
- 赋值公式栏接受已列出的 Decimal 变量名、数字、`+`、`−`、`×`、`÷` 和括号；快捷按钮在光标处插入变量或符号。页面解析优先级与括号并生成 AST v1，非法公式会即时提示且不能保存；输入文本不会直接交给后端执行。可选的保留小数位会生成外层 `Round`。后端 AST 还支持其他节点，正式编辑器可继续扩充类型提示。
- 变量引用提交 `StableKey`。入口不能作为赋值目标；契约入口和必需出口的类型与方向不可在规则编辑器中改动。
- 区间出口分别维护最小值、最大值，列表出口按行维护同类型候选项并支持排序；每项可选常量或单值表达式。整体保存为一条赋值，不跨规则追加结果。约束与 API 格式见[输出值契约](../back-end/docs/architecture/output-values.md)。
- 保存只进行当前对象的规则校验；整份依赖、必需出口、写入冲突和绑定歧义应以完整校验和发布检查为准。

## 原型验收路径

1. 从规则集的草稿进入已有规则，添加 AND / OR 子组并混合多个条件，查看括号预览和 AST，然后保存规则。
2. 添加常量或表达式赋值，在公式栏输入多个变量并用括号调整计算顺序，或点快捷按钮在光标处插入；非法公式、目标重复、类型不匹配和未保存规则应有明确提示。
3. 查看规则或赋值的删除影响，确认后从演示草稿移除。
4. 在未保存、并发戳过期和线上只读状态下尝试写入，界面应阻止并说明恢复动作。
5. 保存后进入校验与试算；原型结果必须明确标识为演示，正式产品以服务端响应为准。
